# csv_recover — 缺失闭合引号的定界表离线恢复工具

面向一类很窄、很明确的取证场景：旧系统落盘时偶尔**丢掉引用字段的结束双引号**，
普通读表器会把后续真实记录一路吞进同一个字段。本工具在**不删除、不修改任何原字节、
不猜测字段内容**的前提下，结合锚点与字段约束，判断每条逻辑行在现存证据下是
**必然一致（determined）**还是**仍有多种解释（ambiguous）**。

它**不是**通用文件取证或字节修复工具。

---

## 1. 支持的格式（刻意收窄）

只识别四类 ASCII 字节：

| 字节 | 含义 |
| --- | --- |
| `,` (0x2C) | 字段分隔 |
| `LF` (0x0A) | 记录换行（唯一的记录分隔符） |
| `"` (0x22) | 双引号，引用边界或转义 |
| 其它字节 | 字段数据；`CR` 也是普通数据字节 |

文法（无歧义写法）：

```
record = field ("," field)*
field  = quoted | unquoted
quoted   = DQUOTE quoted-char* DQUOTE
quoted-char = 普通字节 | DQUOTE DQUOTE     # "" 转义为一个 "
unquoted = 除 COMMA / LF / DQUOTE 外的字节
```

字段内**允许嵌入换行**，因此绝不能按物理换行拆记录。

### 唯一允许的“修补”

当一个引用字段处于**打开状态**时，允许在某个**候选逗号**或**候选记录换行之前**
**插入恰好一个**缺失的闭合双引号：

- 插入是逻辑动作，输出只给出“在哪个字节偏移前插入”，**原输入字节永不改写**；
- 每个打开的引用字段可在其扫描途中遇到的**每个**候选分隔符前产生一个修补候选，
  这正是歧义的来源；
- 引用字段在段尾仍未闭合属于**不可修补**（前面没有分隔符可借），判为硬错误；
- 无引号字段内部出现双引号也属于**不可修补**的硬结构错误。

不支持：删除/替换字节、CRLF 特殊处理、转义逗号、表头推断、编码探测、字段内容猜测。

## 2. 输入约定（JSON）

```json
{
  "data": "K1,\"line one\nline two\"\nK2,plain\n",
  "columns": [
    {"name": "id",   "required": true,  "regex": "[A-Za-z0-9]+"},
    {"name": "note", "required": false}
  ],
  "repair_cap": 1,
  "segment_repair_caps": {"0": 0, "1": 2},
  "anchors": [
    {"byte_offset": 0,  "line": 1, "expect_first_column": "K1"},
    {"byte_offset": 23, "line": 2, "expect_first_column": "K2"},
    {"byte_offset": 33}
  ]
}
```

### 字段

- `data`：ASCII 字符串（或字节数组）。非 ASCII 直接报输入合同错误。
- `columns`：固定列数与每列约束。
  - `required: true` 时该字段不允许为空串；
  - `regex` 给定时用 `re.fullmatch` 校验字段值。
- `repair_cap`：默认的**每段**补引号上限。
- `segment_repair_caps`：可选，按段下标覆盖上限。**每个相邻锚点区间独立计数**，
  一段用满不影响另一段。
- `anchors`：锚点数组，按字节位置落在**行首**。
  - `byte_offset`：字节偏移；
  - `line`：从 1 开始的逻辑行号；
  - `expect_first_column`：该锚点所在行首列的预期值；
  - `sentinel`：尾哨兵标记（一般无需手填）。

### 锚点合同

- 文件起点（偏移 0）视为逻辑第 1 行锚；
- 文件尾视为**最后一行之后的哨兵锚**，不带首列预期；它可以带行号
  （此时固定末段记录数），也可以省略行号（末段记录数开放，可能产生歧义）；
- 已有锚从该字节位置开始解析，区段止于下一个锚之前；
- 内部锚可以省略行号：此时它只约束字节边界与首列，**不**给前一段强加记录数合同；
  工具会在相邻带号锚之间插值出仅用于显示的行号，并标记 `line_interpolated`；
- 出现的行号必须严格递增；锚点定义本身非法（越界、重复偏移、非整数行号等）是
  **致命用法错误**，退出码 2。

### 记录数合同

末锚是“最后一条记录之后”的边界，因此一段含 `r1 - r0` 条记录（不是 `+1`）。
只有两端锚点都**原始携带**行号时才强制记录数；否则记录数开放。

## 3. 输出语义

按**逻辑行号**输出，每段独立。

- `determined`：**所有**最少修补解释在该行都同时同意
  1. 源字节范围 `byte_range` / 字段 `raw_range`；
  2. 每个字段值；
  3. 本行补引号位置 `repairs` / `repair_at`。

  三者全一致才能认作可恢复事实。
- `ambiguous`：最少解释不止一个且在该行有分歧。输出**两种相异解释**在该行的局部
  结果，各自带整段相容证据：

  ```
  evidence: prefix_repairs + this_record_repairs + suffix_repairs
            == segment_total_repairs（该段最少补引号数）
  ```

  即该局部结果能接上某个前缀和某个后缀，拼成一条达到段内最少代价的完整解释。
  某逻辑行在一种解释里被相邻记录吞并、在另一种里存在时，会给出 `present: false`
  的“该行缺失”局部结果。
- `isolated`：该段无法满足区间合同。**仅隔离该段**，相邻证据完好的段照常交付。
  段状态 `status` 与原因 `reason`：

  | reason | 含义 |
  | --- | --- |
  | `repair_cap_exceeded` | 解除上限后可解析，但最少补引号数超过该段上限；诊断给出 `unbounded_minimum_repairs` |
  | `variant_cap_exceeded` | 单状态候选解释数超过 `--variant-cap`（保护性截断） |
  | `first_column_mismatch` | 结构可解析，但没有任何解释的首列等于锚点预期；给出 `available_first_columns` |
  | `structural_hard_error` | 存在不可修补字节（无引号字段内的引号、段尾仍打开的引用）；给出 `first_structural_error_offsets` |
  | `unsatisfiable_contract` | 其它无法满足记录数/列数合同的情况 |
  | `empty_segment` | 两个锚点落在同一字节位置 |

### 证人（witness interpretations）

每个非隔离段最多重建**两条相异的、贯穿整段的完整最优解析**作为佐证，用边游走
（edge walking）得到，并按全局签名去重。证人只在满足合同的终止态收束。

## 4. 算法：为什么不需要枚举完整解释

朴素做法会枚举 2^N 条完整解析（N 个独立二选一），不可行。本工具只在
**记录边界状态**上做动态规划：

1. **字段级**：记忆化解析每个字段起点，产出全部候选 `FieldOutcome`（结束位置、
   补引号代价 0/1、解码值、修补偏移）。
2. **记录级**：记忆化枚举从某字节起点出发、列数与字段约束都合法的全部
   `RecordOutcome`，按字段内容签名去重；记录级**不**套用段上限，避免提前剪掉
   “局部贵、全局最优”的路径。
3. **前向 DP**：状态为 `(字节位置, 已产出记录数)`，Dijkstra 求到每个状态的最少
   补引号数，并保留所有满足最优距离的边。
4. **后向 DP**：在反向边上按**终止记录数分别**求每个状态到 EOF 的最小后缀代价，
   从而既强制锚点记录数合同，又保留等代价替代边。
5. **行事实判定**：一条边属于某个最优合同解释，当且仅当
   `dist[from] + edge.cost + admissible_suffix(to) == total`。把这些边按逻辑行
   汇总局部结果摘要：摘要唯一即 determined，否则 ambiguous。
6. **证人重建**：在最优边子图上 DFS，分支各自持有完整路径，收满两条相异解析即停。

状态数随记录边界数**线性**增长，与独立二选一的数量指数无关。400 个独立修补决定的
夹具（`08_scale_400`）在普通机器上约 0.1 秒完成，且断言前向状态数为线性。

## 5. 命令行用法

```bash
# 人类可读文本（嵌入换行显示为 \n，嵌入引号显示为 \"）
python3 -I csv_recover/recover.py path/to/input.json

# 机读 JSON
python3 -I csv_recover/recover.py --json path/to/input.json

# 写 JSON 报告到文件
python3 -I csv_recover/recover.py path/to/input.json -o report.json
```

退出码：`0` 全部段可交付；`1` 至少一段被隔离；`2` 输入合同本身非法。
`--variant-cap` 控制单状态保留的候选记录解释数（默认 128），仅用于保护性截断。

> 建议始终用 `python3 -I` 运行：隔离模式不加载当前目录 / `PYTHONPATH`，
> 避免不可信数据目录里的同名模块（如 `json.py`）被导入。

## 6. 可复跑夹具

夹具由生成器在每次运行时写入独立空目录，数据只是字节串、绝非代码：

```bash
# 生成全部夹具到 fixtures/
python3 -I tests/make_fixtures.py fixtures

# 断言式测试（自建临时目录，不依赖磁盘旧状态）
python3 -I tests/test_recover.py
```

| 夹具 | 覆盖点 |
| --- | --- |
| `01_multiline_ok` | 正常多行字段、`""` 转义、零修补全确定 |
| `02_repair_ok` | 单个缺失闭合引号的恢复 |
| `03_anchor_firstcol_wrong` | 锚点首列错误 → 隔离并给可用首列 |
| `04_cap_exceeded` / `04b_cap_relieved` | 受限修补隔离 vs 放宽后可交付对照 |
| `05_ambiguous` | 真等代价二义、含“该行存在/缺失”两种局部结果、两条证人 |
| `06_ambiguous_edge_determined` | 二义段两侧的确定行仍可交付 |
| `07_isolated_neighbour_ok` | 硬结构错误隔离，相邻完好段照常交付 |
| `08_scale_400` | 大量独立二选一，验证不枚举完整解释且状态线性 |

## 7. 边界与明确不做的事

- 不修复、不回写源文件；所有“修补”都是报告里的字节偏移；
- 不在无锚点依据时猜测字段内容、列含义或编码；
- 不处理本文法之外的任何 CSV 方言（CRLF、反斜杠转义、分隔符转义等）；
- 不做通用文件 carving / 通用字节取证；
- 锚点被视为可信的独立证据；锚点自相矛盾是用法错误而不是数据歧义。
